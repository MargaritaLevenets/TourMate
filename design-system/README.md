# design-system/

Правила, за якими токени й компоненти складаються в цілісний продукт.

Різниця проста:
`tokens/` — це **значення**, `components/` — це **цеглинки**,
`design-system/` — це **правила**, як з них будувати.

## Що сюди класти

| Файл | Про що |
|---|---|
| `grid.md` | сітка й поля сторінки, поведінка на різній ширині екрана |
| `typography-scale.md` | ієрархія тексту: заголовки, основний текст, підписи |
| `states.md` | наскрізні стани: завантаження, порожньо, помилка, немає мережі |
| `accessibility.md` | контраст, розміри зон натискання, читабельність на сонці |
| `motion.md` | анімації та переходи — коли доречні й наскільки швидкі |
| `voice.md` | тон текстів інтерфейсу: як формулюємо кнопки й повідомлення |

## Рамки, задані продуктом

- **Mobile-first.** Проєктуємо під телефон. Ширший екран — приємний бонус, не мета.
- **Читається на вулиці.** Високий контраст, великий текст.
- **Короткий погляд.** Під час екскурсії гід дивиться в екран 5–10 секунд.
  Головне має зчитуватися одразу, без вчитування.

## Статус

Порожньо — правила формулюємо, коли назбирається достатньо компонентів,
щоб було що узагальнювати.
