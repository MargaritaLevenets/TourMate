# CLAUDE.md

Інструкції для Claude Code в цьому репозиторії.

## Що це за проєкт

**TourMate** — веб-застосунок-помічник для приватного екскурсовода. Усе про його тури
в одному місці, у телефоні. Повний опис ідеї — в [idea.md](idea.md).

Це **дизайн-репозиторій**, а не кодова база. Тут живуть дослідження, вайрфрейми,
токени, компоненти й хендоф. Продакшн-коду застосунку тут поки немає.

## Хто користувач репозиторію

Дизайнерка, яка працює у Figma й **не має досвіду програмування**.

- Спілкуйся **українською**.
- Пояснюй простими словами, без жаргону. Якщо термін потрібен — розшифруй його одразу.
- Не припускай знання git, терміналу чи синтаксису коду.
- Коли пропонуєш дію в терміналі — поясни, що вона робить і що зміниться.

## Ключові рішення по продукту

- **Платформа:** веб-сайт, спроєктований під телефон (mobile-first). Відкривається
  у браузері, нічого не треба встановлювати. Офлайн і PWA — можлива пізніша надбудова.
- **Аудиторія:** приватний гід, який працює сам на себе. Туристи застосунком
  **не користуються** — це особистий інструмент гіда. Не проєктуй екрани для туриста.
- **Мова інтерфейсу:** українська.

## Чотири розділи застосунку

Порядок навмисний — це черга роботи, а не просто список:

1. **Розклад** — календар турів, записи туристів, нагадування про найближчий тур.
   Робимо першим: без нього решта не має каркаса.
2. **Тур наживо** — маршрут по точках, тексти й підказки для гіда під час екскурсії.
   Друге: це те, заради чого гід відкриє застосунок під час роботи.
3. **Матеріали** — бібліотека фото, фактів, посилань і нотаток, які гід чіпляє до турів.
4. **Клієнти й гроші** — картки туристів, статуси оплат, підсумки заробітку.

Не розширюй обсяг першої версії за межі поточного розділу без запиту.

## Структура репозиторію

| Папка | Що там лежить |
|---|---|
| `research/` | Дослідження: інтерв'ю, аналіз конкурентів, сценарії. Скриншоти — у `research/screens/` |
| `wireframes/` | Чорно-білі схеми екранів: що де стоїть, без кольору й краси |
| `concept/` | Візуальний напрям: настрій, референси, пробні екрани «як це виглядатиме» |
| `tokens/` | Токени дизайну: кольори, шрифти, відступи, радіуси — як значення, а не картинки |
| `components/` | Окремі елементи інтерфейсу: кнопки, картки, поля, навігація |
| `design-system/` | Правила, як усе це складається докупи: сітка, типографіка, стани, доступність |
| `handoff/` | Що віддаємо в розробку: специфікації екранів, експорти, нотатки для розробника |

Кожна папка має власний `README.md` з поясненням, що саме туди класти.

## Правила роботи

- **README.md у корені — живий індекс.** Додаєш файл у папку — онови відповідний
  рядок у README, щоб індекс не застарів.
- **Токени — джерело правди для кольорів і розмірів.** Не вписуй значення кольорів
  чи відступів прямо в компоненти й макети, якщо їх можна взяти з `tokens/`.
- **Формат файлів:** текст — у Markdown (`.md`), демо й прототипи — самодостатній
  HTML одним файлом (без зовнішніх бібліотек і CDN).
- **Іменування файлів:** латиницею, малими літерами, через дефіс — `tour-live-map.md`,
  а не `Тур наживо.md`. Так посилання не ламаються.
- **Мова вмісту** файлів — українська; **назви файлів** — латиницею.

## Статус

Ідея описана, структура репозиторію готова. Дизайн ще не починався.
